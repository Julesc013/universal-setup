# Registered publisher C SDK client

This is an active development interface. The context and failure controls build locally; selected installed SDK reentry and public verification have hosted positive evidence, while generic recovery and complete lifecycle qualification remain incomplete. This document does not declare release or production support.

Include `usk/usk_publisher_client.h` and call `usk_context_create_publisher_v1(local_config, publisher_config, &context)`. The separate sized endpoint configuration is copied during creation. It selects an existing administrator-configured service and grants no registration, elevation, raw-volume or target authority. Creation performs no service activation.

The existing `usk_config_v1` prefixes, four original entry points, ABI 1.0 version result, allocator pairing and borrowed response lifetime remain unchanged. The added factory is an opt-in symbol; its presence is separate from the baseline version getter. Non-Windows factory calls return `USK_STATUS_UNSUPPORTED_VERSION` with a null context.

The command API accepts the same public requests. Ordinary planning keeps the optional local configuration. Selected effects and verification use the authenticated service route. A publisher context owns recovery.inspect, recovery.plan and recovery.apply; these never fall through into local filesystem recovery. The complete authenticated request, original plan identity, reviewed recovery digest and selected action reach the native owner unchanged.

Native maintenance recovery is an unfinished development path. It now connects read-only inspection and planning to reviewed finalize for an ended original post-commit repair/move/uninstall. Actual protected inspection, matching reviewed observations, fresh native writer admission and source-free completion must qualify together. This implementation has not yet passed its added public SDK interruption cohort. Native install recovery, precommit recovery, completed-history/reconnect and rollback remain unavailable on this route. Unsupported rollback is refused before a writer; it never means forward recovery.

The explicit publisher context advertises usk.recovery_report.v2 and usk.recovery_plan.v2 through its command graph. Ordinary local contexts retain their existing v1 output contracts and ABI layouts. The versioned native documents bind original intent/custody, current installed revision, complete committed lease history, empty pending-lease names, namespace/content observations and transaction/effect history. These are observations, not lease or effect authority.

Inspect and plan acquire read/list handles without acquiring a writer lease, creating metadata or installing publication hooks. Old holders require native PID plus birth-identity termination; a lost heartbeat or caller assertion does not suffice. Pending lease work, incomplete original custody or changed membership refuses. Unknown reconciliation offers no action. The finite checks do not promise continuous filesystem monitoring. Finalize is offered only for the supported observed predicates; apply rebuilds the complete observation and exact plan before acquiring its own writer lease and repeating the existing effect fences.

A missing or inconsistent completion remains UNKNOWN after possible dispatch. The reply validator binds completion to the same reviewed pre-effect v2 plan and checks its distinct final journal/effect hashes. An older four-field selector remains a private lookup; it cannot replace the complete public recovery request.

Each invocation owns its UNKNOWN response before transport can send request bytes. Lost, malformed, mismatched or allocation-failed replies after possible dispatch return `USK_STATUS_ERROR`, JSON status `unknown` and error code `publisher_outcome_unknown`. This does not establish whether effects occurred. Do not blindly repeat an apply; inspect or recover the bound operation using its actual reviewed contract.

The payload `usk.publisher_client_outcome.v1` retains the canonical public request SHA-256 and bounded caller-supplied operation/recovery identity. These fields are correlation data, not native evidence or authority. Full requests, archive paths and payload bytes are not copied into uncertainty output. The identity receipt has a 64 KiB bound; request and response parse limits have separate meanings.

Only the concrete transport can establish pre-dispatch refusal. Validated native refusal and recovery-required outcomes remain distinct from transport uncertainty. Failure never selects the privileged legacy client or retries through local mutation.

Response bytes remain borrowed until the next call on the same context or destruction. Copy retained results before that boundary. Serialize calls to one context; independent contexts own separate buffers. No transport callback is part of the public ABI.
